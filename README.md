# FuturoGen - AI模型训练平台

一个基于Python Flask的Web应用，用于YOLOv8、11目标检测模型的图片标注、数据集管理、模型训练和模型导出，由Boyan开发。旨在为AI开发者和研究人员提供一个完整的、易用的目标检测模型训练解决方案。
## 创新特性
1. 多层次AI辅助标注 ：大模型+PT模型的双重AI辅助体系
2. 数据增强闭环 ："小数据→简单模型→辅助标注→大数据→精确模型"的完整循环
3. 实时检测集成 ：将训练和部署统一在一个平台
4. 项目级隔离 ：多项目并行开发，资源完全隔离
5. 全流程自动化 ：从数据标注到模型部署的完整自动化
6. 跨平台兼容 ：支持Windows、macOS、Linux多平台部署
## PT模型辅助检测的核心价值 （待发布）
### 1. 降低数据门槛
- 快速启动 ：仅需50张标注图片即可训练初始模型
- 渐进改进 ：通过模型辅助逐步扩充高质量数据集
- 成本控制 ：减少人工标注工作量，提升标注效率

## 解决的核心问题
### 1. 数据标注效率低下
- 传统问题 ：手动标注大量图片耗时费力，标注质量不一致
- 解决方案 ：集成大模型辅助标注功能，支持自动目标检测和智能标注生成
### 2. 模型训练门槛高
- 传统问题 ：需要复杂的环境配置和命令行操作
- 解决方案 ：提供Web界面化的训练流程，实时显示训练进度和日志
### 3. 数据集管理复杂
- 传统问题 ：手动组织数据集目录结构，容易出错
- 解决方案 ：自动化数据集划分和目录结构生成
### 4. 实时检测部署困难
- 传统问题 ：RTSP视频流检测需要复杂的配置
- 解决方案 ：内置RTSP实时检测功能，支持多路视频流
### 5. 数据增强循环困难
- 传统问题 ：缺乏有效的数据增强和迭代标注机制
- 解决方案 ：PT模型辅助检测，实现"小数据训练→模型辅助→数据增强→高精度模型"的良性循环

## 功能特性

1. **项目管理**：创建、列出、删除项目
2. **图片管理**：
   - 上传单张或多张图片
   - 通过ZIP文件批量上传图片
   - 拖拽上传图片
3. **图片标注**：
   - 基于Web的边界框标注功能
   - 图片间导航（上一张/下一张）
   - 项目内标签（类别）管理：添加、编辑、删除
   - 标注数据实时保存到数据库，并自动生成YOLOv8 `.txt` 格式的标注文件
   - **🆕 大模型辅助标注**：集成AI大模型进行智能目标检测和自动标注，大幅提升标注效率
4. **数据集划分**：批量将图片标记为训练集、验证集、测试集或未分配
5. **模型训练**：
   - 实际调用 `ultralytics` 库进行模型训练
   - 训练任务在后台线程中运行，前端实时显示训练日志和进度
   - 自动准备训练所需的数据集目录结构和 `data.yaml` 文件
6. **模型导出**：将训练好的模型导出为ONNX、TorchScript等多种格式
7. **🆕 RTSP实时检测**：
   - 支持RTSP视频流实时目标检测
   - 实时显示检测结果和边界框
   - 支持多路视频流同时检测
   - 可配置检测参数和阈值

## 使用说明

1. **创建项目**：在首页点击"创建项目"按钮，输入项目名称和描述

2. **上传图片**：
   - 进入项目详情页，点击"图片管理"
   - 可以上传单张/多张图片、ZIP压缩包或通过拖拽上传

3. **图片标注**：
   - 在项目详情页点击"图片标注"
   - 先创建标签（类别），然后选择标签在图片上绘制边界框
   - 使用"上一张"/"下一张"导航到不同图片
   - 点击"保存标注"保存当前图片的标注结果
   - **🆕 大模型辅助标注**：点击"手动大模型识别标注"按钮，大模型将自动识别图片中的目标并生成标注框

4. **数据集划分**：
   - 在项目详情页点击"数据集划分"
   - 选择图片并设置为训练集、验证集、测试集或未分配

5. **模型训练**：
   - 在项目详情页点击"模型训练"
   - 点击"开始训练"按钮启动训练过程
   - 可实时查看训练进度和日志

6. **模型导出**：
   - 训练完成后，在项目详情页点击"模型导出"
   - 选择需要的导出格式（ONNX、TorchScript等）
   - 点击"导出"按钮完成模型导出

7. **🆕 RTSP实时检测**：
   - 在首页点击"RTSP实时检测"进入实时检测页面
   - 输入RTSP视频流地址
   - 选择检测模型和项目
   - 点击"开始检测"启动实时目标检测
   - 可实时查看检测结果和调整检测参数

## 道路调查任务

在项目导航进入“道路调查”，或访问 `/project/<项目ID>/road-surveys`。

1. 从磁盘根目录发现道路，或新建任务，确认道路、调查日期、地点编号与车型映射。
2. 每个方向按固定机位建立序列；依次加入第一张、第二张卡目录，并填写首段拍摄时间和换卡停录秒数。
3. 扫描预览视频清单。视频按数字文件名排序，起止时间按实际时长累加，不从 `00000.MTS` 猜测时间。
4. 复用素材配置页画好的区域，映射到主路、辅路；也可以在调查页直接画多边形。方向名称手动填写，无需自动判断朝向。计数线和通行箭头只在可选的过线模式下需要。画面变化须新增机位；同方向同一主辅路的多个机位不能重复覆盖相同时段。
5. 确认时间表后开始。默认按车辆底边中心进入区域计数，同一追踪ID在每个区域只计一次；同一机位的连续视频延续追踪。
6. 两个方向分别导出主路、辅路，共四份 Excel。第一版只生成“5分钟”Sheet，保留已确认模板的21列表头；按主辅路总量统计，不虚填车道。

不足5分钟或停录形成的不完整时段以黄色和批注标记，完全没有录像的时段留空；零表示有效录像中未观测到该车型。ZIP 包同时包含逐车计数 JSONL 明细和调查配置、视频时间清单。`中巴车`、`作业车` 需明确映射或选择“不纳入模板”，被排除的事件仍记录在明细中。

任务配置与机位级检查点保存在新增的 `yolov8_platform.road_survey_task` 表，原有表不变；启动时自动建表。结果和审计文件保存在 `instance/road_surveys/<任务ID>/`。停止后保存当前批次完成的精确帧断点（追踪器、去重、累计统计、录像覆盖和审计偏移），恢复时从下一帧继续；运行中按批次约每5秒保存，进程异常退出可从最近断点恢复；旧任务没有帧断点时未完成机位从头重跑；修改配置会使既有结果失效。任务与视频所在机器绑定。

### 多道路并行与80GB服务器

道路调查使用独立计算队列，目录扫描使用独立的双线程队列。每条道路各自加载模型、使用独立CUDA流、追踪器和计数器，互不共享模型预测状态。抽查回放占用同一计算队列的名额；停止某条道路不会停止其他道路，尚未开始的排队任务可直接取消。原有单素材推理仍使用其旧队列。

本地默认1路；89服务器可将 [config/road-survey-89.env.example](config/road-survey-89.env.example) 中的设置合并到现有 `.env` 后重启：

```dotenv
ROAD_SURVEY_WORKERS=2
ROAD_SURVEY_BATCH_SIZE=0
```

并行数支持1至8。建议在80GB显卡先测试2路，再比较3/4路的总吞吐量。批量0表示根据显存、分辨率和并行路数估算；页面可为每条道路手动设置1至64。12GB及以下显卡保持原先的保守自动批量。CUDA显存不足会减小批量并重试尚未计数的检测，保持帧顺序；单帧仍不足时明确报错。可变尺寸道路推理使用各自的PyTorch模型，不复用固定批量TensorRT引擎。

页面顶部显示当前并行名额、运行与排队数量。这里的并行上限以单个Web进程为单位；请采用单Web进程启动，避免多个Gunicorn进程分别建立队列而重复占用显存。当前进度和停止事件属于运行进程，重启后按最近帧断点恢复，已完成机位跳过。

道路信息中可保存推理分辨率：640、960、1280 或原视频尺寸。原尺寸按模型步长补边（例如1920×1080补至1920×1088），本地小显存使用单帧批量，大显存按并行预算分配批量；提高分辨率会降低处理速度。修改分辨率后需要保存，并从未完成的机位重新运行。

“抽查回放”可选择方向、机位与起始时间，独立生成最多5分钟的带框 MP4。支持原速、暂停、拖动及0.25/0.5倍慢放，录像不足5分钟时只生成实际可用时长；停录间隔显示无录像。抽查预热最多10秒追踪并独立复算，不覆盖正式统计，边界计数可能存在差异。抽查任务及配置快照保存在 `road_survey_review` 表，视频和明细保存在任务目录的 `reviews/` 子目录，可取消或重新生成。

抽查完成后可点击“导出Excel”，已有抽查不必重新推理。工作簿包含“5分钟”（模板21列，主辅路分行）、“车型汇总”（原始车型及映射、全部/纳入/排除计数）、“逐车明细”和“抽查说明”。不完整时段标黄并附覆盖秒数批注，未配置区域留空；Excel严格使用抽查生成时保存的配置与事件，不读取后来修改的道路配置。

## 许可证

本项目由Boyan开发，仅供学习和研究使用。

帧断点保存在 `instance/road_surveys/<任务ID>/<机位>.checkpoint`，仅读取本机服务生成的文件。使用“全部重新运行”会重建断点；配置或源文件变化时旧帧断点不复用。恢复MTS时采用顺序解码定位，定位阶段不做模型推理和重复计数。正常停止需等待当前GPU批次完成后才显示停止；强制退出可能回退到最近一次周期断点。

导出表的“地点名称”按当前5分钟时段的视频来源标注“一卡”“二卡”等，跨卡时标注“一卡、二卡”，不拆分或重复累计该时段。正式任务按方向、主辅路选择来源机位；抽查按实际抽查窗口选择来源卡。旧正式结果首次重新下载会刷新报表格式，无需重新推理。

普通机位目录直接存放视频时不标卡号；仅目录名明确为 `1`、`2`、`一卡`、`二卡`、`第2张卡` 等才识别为卡。旧配置和旧扫描结果会根据已保存的视频来源目录兼容判断，顺序编号不再冒充卡号。
